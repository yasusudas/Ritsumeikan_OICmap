# 地図のオフライン利用

## 動作

オンラインで地図ページを一度開き、自動保存が完了すると、日英両方の全階地図、教室検索、検索外周、施設リング、プリンター案内図、店舗の基本情報と画像をオフラインで利用できる。

別途ダウンロード操作やホーム画面への追加は不要。「このサイトについて」に、保存待ち・保存中・保存完了・失敗を表示する。初回の保存完了まではオンライン接続が必要。

## 初期表示への配慮

1. 通常の初期表示に使うリクエストと地図操作を優先する。
2. ページのload、地図・検索・食事データの初期処理が完了するまで待つ。
3. 最後のキー・ホイール・ポインター操作から3秒待ち、requestIdleCallbackでブラウザーが空いたときにService Workerを登録する。
4. ドラッグ・ピンチのポインターが押されたままの間、非表示タブ、オフライン中は開始を延期する。requestIdleCallbackのない環境では3秒の待機を使う。
5. 保存は低いfetch優先度で1件ずつ行う。ハッシュ付き資産は初期表示で取得済みのHTTPキャッシュを再利用する。保存の開始後は、地図を閉じずに操作を続けられる。

保存対象のSVGをDOMへ展開したり、全階の画像を画面用にデコードしたりはしない。バックグラウンド保存を開始すると通信量・ストレージ使用量は増える。

## 保存対象と更新

- scripts/vite-offline-map-plugin.mjsが、実際に出力した日英HTML、ハッシュ付きSVG・JS・CSS・検索JSON等と、地図用の画像・アイコンから保存リストを生成する。
- 出力内容とService Worker本体からリビジョンを計算し、更新ごとに別のキャッシュへ保存する。隠しファイルや編集用HTML、元の編集用検索JSON、ライブAPIは事前保存しない。
- 全件が成功するまでService Workerのインストールを完了させない。途中で失敗した場合は新しい部分保存を破棄し、前の正常な保存を残す。
- 更新版は、既存タブを閉じてから有効になる。利用中の旧版が使う資産を保存途中に削除しない。
- 有効化後に、このアプリの旧キャッシュだけを削除する。
- バージョン管理した同一内容の静的資産は、要求時のOriginヘッダー差によって保存内容を見失わないよう照合する。

## 通信が必要な機能

運行情報、生協の当月営業カレンダー、当日のキッチンカー情報などのAPI応答はオフライン用に保存しない。利用不能時は各機能の既存の取得失敗・確認不可の表示を使う。静的な店舗情報から分かる通常営業時間と、当日の情報を区別する。

時刻表等、保存対象外のページをオフラインで開くと、オンライン接続が必要な旨と地図へのリンクを表示する。別URLのまま地図のHTMLを返すことはしない。認証が必要な編集画面はService Workerの対象外。

保存は同じブラウザー・同じサイトの保存領域を使う。別ブラウザーや別ドメインには引き継がれない。サイトデータの削除やブラウザーによる保存領域の回収後は、オンラインで再保存が必要。[保存領域の仕様](https://developer.mozilla.org/en-US/docs/Web/API/Storage_API/Storage_quotas_and_eviction_criteria)
