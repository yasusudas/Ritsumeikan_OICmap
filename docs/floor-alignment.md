# 階切り替えの共通座標補正

## 対象と基準

Version3.2の閲覧画面で、1Fを基準に2〜5Fの図面を棟ごとに位置合わせする。階を切り替えた後も同じ地図座標・倍率を保持する。原図や編集用JSONを書き換えず、閲覧用SVGを生成する。

SVGの外寸とviewBoxは区別する。共通の図面座標は1190.55×841.89。H棟上層のviewBox原点8.5は既存の正規化を維持する。A/H棟6〜9Fとプリンター図は今回の位置合わせの対象外だが、表示・操作の回帰検証に含める。

## 位置合わせ

`src/assets/floor-alignment.json` に日英それぞれの基準点、対応する1Fの点、補正範囲、原本SVGのSHA-256を保存する。`src/floor-alignment.js` で倍精度の行列を求め、地図画像とオーバーレイで共有する。画像の表示ピクセルから座標を逆算して補正値を保存しない。

| 範囲 | 対象階 | 基準 |
| --- | --- | --- |
| A棟 | 2〜5F | AS翼北西角・西側と東側のエレベーター記号中心の3点 |
| H棟 | 2〜5F | 北西・北東の外壁角と南西側階段記号中心の3点 |
| B棟 | 2〜5F | 南西・南東の外壁角と北側エレベーター記号中心の3点 |
| C棟 | 2〜4F | 西側エレベーターと北側階段の2点による相似変換 |
| C棟 | 5F | 西側エレベーターを基準に平行移動 |
| D棟 | 2〜3F | 北西の外壁角を基準に平行移動 |
| G棟 | 2F | 外壁と内側壁の3点 |

C棟南側階段やD棟のフロア外形には階による相違があり、それらを同じ形として無理に3点アフィン変換しない。仮想の直交点・平行移動用の点は実測点の検証件数へ数えない。データは図面上の対応であり、現地測量ではない。

## 描画と保存データ

- `scripts/aligned-floor-svg.mjs` と `scripts/vite-map-assets-plugin.mjs` が、最適化済みSVGから閲覧用の補正画像を生成する。既存の食事用1F画像、原図、編集画面は保持する。
- `src/floor-alignment-overlay.js` が図面と同じ範囲で元図形をクリップしてから変換する。元の線・白縁も同じ処理を通し、切断境界へ不要な線を追加しない。
- 施設リングはHTML要素ごとの個別配置をやめ、一つのSVG座標系で円を描く。半径・中心・線・白縁を同じ変換へ含める。色と施設選択の仕様は維持する。
- オーバーレイは実体のSVG要素を配置する。`<use>` と `non-scaling-stroke` の組み合わせで画面上の線が消える問題を避ける。クリップ別のコピーには `data-registration-copy` を付け、論理上の1件と描画インスタンスを区別する。
- 検索フォーカスは補正後の外周全体へ合わせる。保存された外周・施設座標は原図基準のまま。英語の施設記号補正も適用してから階の位置合わせを行う。
- GPS連携用の行列合成関数も用意する。GPS機能本体とその接続は別作業の未コミット変更のため、今回のコミット対象には含めない。
- 地図の基本表示サイズが同じ階移動では、x/y/zoomを再計算せず保持する。画面サイズが変わった場合は従来どおり表示中心を復元する。
- virtual assetの相対URLはページURLから解決してから画像へ渡す。開発・productionの初期表示と再試行で同じ規則を使う。

## ブラウザー照合

`e2e/floor-registration.spec.js` と `e2e/floor-registration-browser.js` で次を検証する。期待値は配信されたSVGのviewBox・変換行列・クリップ範囲と、原本から抽出済みの施設記号データから得る。実装の変換関数を呼んだ値だけで合否を決めない。

1. 各言語で1F→2F→3F→4F→5F→1F、さらに5F→2F→1Fを往復し、表示位置と倍率が保持される。
2. 全7階の施設リング514件の中心・輪郭16点を、実際の円要素のscreen CTMで照合する。
3. 検索1,029項目のうち外周を持つ1,016項目・1,058多角形を全件表示する。全頂点と辺の1/4・1/2・3/4点を照合し、図面とオーバーレイのクリップ範囲も一致することを確認する。
4. 食事・ATM等のカード検索13項目と施設領域12多角形を照合する。
5. 各階のリングと検索枠について、ブラウザーの実スクリーンショットに指定の線色の画素が存在することも確認する。数値上の座標一致と画面上の描画を両方検証する。

WebKitの連続URL切替制限を避け、検索は新しい検証ページで80件ずつ処理する。対象件数を減らしたり再試行で失敗を隠したりしない。判定上限は0.08 CSSピクセル。これはオーバーレイと対応するSVG座標の表示差であり、異なる階の間取り全体や現地座標の完全一致を意味しない。

```sh
pnpm --config.manage-package-manager-versions=false --config.verify-deps-before-run=false test
E2E_CROSS_BROWSER=1 pnpm exec playwright test e2e/floor-registration.spec.js
```

## 文字・見出し・引出線の追加修正

RAINBOWサービスデスクで、棟ごとの矩形クリップが文字を途中で分断する不具合を修正した。前回の座標・リング・検索枠の照合だけでは、この文字分断を検出できていなかった。棟名見出しの黒い背景と白文字、境界を通る引出線にも同じ問題があった。

- `scripts/generate-floor-text-registration.mjs` で、原図のグリフをSVG単位で測り、色・字間・重なりから文字のまとまりを作る。英語の一語が複数のSVGグループに分かれる場合も同じまとまりへ含める。
- `scripts/floor-text-registration.mjs` が文字を図形のクリップ対象から取り出す。文字列全体へ一つの行列を適用し、元の字形・色・字間・継承スタイルを保持する。境界をまたぐ棟名見出しは黒い背景と白い文字を一体で扱う。
- 境界をまたぐ直線の引出線は、元の頂点を共通補正へ通して連続した線へ描き直す。途中をクリップして二重線や隙間を作らない。
- 補正対象の日英2〜5Fは8,515グリフ、見出し等100図形、引出線18本を保持する。元のSVGと編集用座標は変更しない。図面が変わった場合は生成データを更新し、最適化後SVGのハッシュ不一致を解消してからbuildする。

`e2e/floor-text-registration.spec.js` で日英・全7階の文字数・重複・色・元座標とクリップの有無を検証する。文字と見出しの意図した移動だけを戻し、原図と実ブラウザーの画像を1倍・2倍で画素比較する。H棟上層は文字が通常の図面パスへ展開されているため、空の文字マスクを比較せず、配信SVG全体が原図の最適化結果と完全一致することと実スクリーンショットを確認する。引出線の端点も確認する。

追加検証は日英×PC／スマートフォン相当×Chromium／WebKitの8条件すべて成功した。全7階を巡回し、文字・見出しの1倍／2倍の画像比較96組は画素差0。H棟上層は8条件で配信SVG全体の完全一致を確認した。引出線の端点、全施設リング514件・検索多角形1,058件・施設領域12件の8条件の再照合も成功。pnpm testは195件成功。詳細は [floor-text-validation.json](./floor-text-validation.json) を参照。この追加変更後は文字検証と全施設・全検索領域の照合を再実行する。上の周辺回帰133件は文字修正前の実行履歴として保持している。 初回の統合実行で停止したH棟上層の文字比較4件は、同一SVGの全図面PNG比較と、変更した文字の厳密な画素比較を分けて再確認した。最終文字テスト8条件はすべて成功し、初回ログも保持する。

## SVGを差し替える場合

文字の生成データも更新する。図面の基準点とクリップ範囲を測り直し、`floor-alignment.json` の対応点とSHA-256を更新する。施設記号を変えた場合は既存の施設リング補正表も再生成する。基準に使った点だけでなく実図とオーバーレイの描画を確認し、上記の全件照合を再実行する。
