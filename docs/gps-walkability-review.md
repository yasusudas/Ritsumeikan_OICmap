# 1F 通路・接続候補のレビュー

2026-10-24。Version3.2 専用のオフライン候補生成。公開アプリの測位・検索・施設リング・Sitesには適用しない。

## 再生成

既存の Node.js / `@playwright/test` と Chromium、Python 3 + NumPy + OpenCV を使用する。新規依存の追加は不要。ただし Python のライブラリが利用可能な環境を指定する。

```sh
node scripts/gps/generate-walk-review.mjs --out /tmp/oic-walk-review-1f
# Intel 向け NumPy / OpenCV を入れた Apple Silicon 環境の場合
node scripts/gps/generate-walk-review.mjs --python-arch x86_64 --out /tmp/oic-walk-review-1f
```

`--python` で Python 実行ファイルを指定可能。スクリプトは作業ブランチが Version3.2 であることを検査する。出力先内の同名ファイルは再生成されるため、レビュー済みの版は別ディレクトリに保存する。

## 成果物と確認方法

- `1F-overview.png`: 全候補を重ねた全体図。
- `1F-A.png`, `1F-B.png`, `1F-H.png`, `1F-CD.png`, `1F-G.png`: 棟別の拡大図。同名 SVG も出力する。
- `1F-areas.png`: 通路領域と部屋境界の確認画像。
- `review.html`: 外部通信不要の単体HTML。原図・領域・中心線・接続・E/D/V・番号を切替可能。候補番号や部屋名で検索し、一覧から該当位置へ移動できる。
- `candidates.json`: 全候補の座標、根拠、未解決接続、入力SHA-256。全件 `enabled:false`, `review:pending`。
- `review-list.csv`: W/R/E/V/D の番号と座標。入力変更や抽出条件変更後の番号維持は保証しない。修正指示はこの生成版の番号で行う。

W は通路領域、R は中心線、E は原図の小三角記号、V は既存の階段・エスカレーター・EV、D は部屋境界から幾何的に仮置きしたドア候補。青線が中心線、橙点線が未確認の接近線。**Dは実際の扉を検出した結果ではない。** 部屋ごとに最大1点なので複数ドアは網羅しない。Eも記号の意味と実際の通行可否を確認する必要がある。

ユーザーは「Dxx は壁なので削除」「Exx から廊下へ接続」「Wxx のこの部分は立入不可」のように番号と修正内容を指定する。画像への書き込みでも可。採用・除外・位置修正を確定してから別途本番用の経路網を作る。

## 抽出方法と限界

1. `src/assets/floors/ja/1F.svg` を既存 outline-kit で読み、変換適用済みの塗り形状を抽出。
2. 灰色3段階を屋内床候補、ベージュを屋外候補とし、他の大きな塗り形状を除外。TRY SQUARE / 空のプラザ / テラスは別の共有空間候補。灰色・共有空間は通行許可を証明しない。
3. SVG共通座標の1単位グリッドにラスタライズ。連結成分を領域とし、細線化で中心線を生成。膨張・隙間埋めは行わず、元図の分断を維持。
4. `public/manual-search-index.json` の検索多角形は境界の参考に使う。複数室や廊下を包む検索領域もあるため、実壁として一律に差し引かない。
5. 既存施設リングから階段・EV等の記号中心を取得。これは着地点・ドア位置の確定値ではない。階間接続は作らない。
6. D は通路候補に近い部屋境界をサンプリングして作る。E/V/Dから床候補までの隙間を含む接近線はすべて未確認であり、壁を横切らないことは保証しない。床候補内の接近線は領域内探索で生成。

1F原図・施設リング・検索多角形と同じ座標フレームを使う。後続階へ展開する際は既存の階登録変換との整合確認が必要。生のSVG線は文字・引出線・図記号と壁を区別できないため、確定壁として抽出していない。実施設での通行可否・営業時間・立入制限・正しい扉位置は人の確認が必要。
