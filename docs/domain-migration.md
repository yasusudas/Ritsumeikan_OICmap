# 手動移転案内と計測

## 配信とURL

- `rits-oic-map.vercel.app` の完全一致条件で、既存HTMLのURLだけに独立した案内を返す。200、`X-Robots-Tag: noindex, follow`、HTMLにも `noindex,follow`。案内には地図コード・閉じる操作・自動遷移がない。
- 対象は日英トップ、アクセス、フード、規約、プライバシー、時刻表、編集画面、隠し時刻表。末尾スラッシュなし・あり・`index.html` を含む。未知のURLは404。
- `vercel.json` は `routes` を使う。旧ホストの案内を **filesystemより前** に処理する必要があるため。通常の `rewrites` はファイル確認より後に配置され、既存のトップHTMLには不十分。
- 旧ホストのrobotsだけは `legacy-robots.txt` をテキストで返し、案内のnoindexを読めるようにする。新ホストのrobots、sitemap、静的アセット、SW、確認ファイル、APIは既存配信を維持する。
- ボタンは同じタブの通常のリンク。新ホストは固定値。パス・クエリ・ハッシュを別々にコピーし、`oicmap_migrated=1` を付ける。`utm_*`、`gclid`、`_gl` などの値は変更しない。移転用UTMは付けない。
- 本文とボタンは `/en` 以下で英語。新サイトでは移転モーダルを表示しない。

## GA4

全15ページの重複したタグ設置を `public/analytics-init.js` にまとめた。読み込みは同期で、以下の順序にする。

1. 新ホストの移転マーカーの有無をメモリに保存。
2. マーカーだけをURLから削除。既存のhistory state、他のクエリ、教室ハッシュは維持。
3. GA4を一度だけ初期化し、実タグを非同期ロード。

手動の `page_view` は追加せず、既存の自動ページビューに任せる。GA4管理画面の拡張計測設定は変更しない。GA4の標準 `page_location` はフラグメントを省くが、ブラウザURLと教室選択には残る。

| イベント | 意味 |
| --- | --- |
| `domain_migration_notice_view` | 独立案内のドキュメントを表示 |
| `domain_migration_link_click` | 案内リンクをクリック。連打しても同じドキュメントでは一回 |
| `domain_migration_marked_arrival` | 新サイトにマーカー付きURLで到着 |

最後のイベントは実クリックの証明ではない。共有URLや再訪でも発生する。新サイトでURLが整理された後のリロードでは発生しない。旧・新それぞれのドキュメントで発生するページビューは正常である。

計測を拒否・遮断してもリンク移動は妨げない。クリック送信の完了待ちや `preventDefault` は使わないため、タグ未ロード時や即時離脱時の旧側イベントには欠測の可能性がある。

## 公開前・公開時の確認

- `node --test tests/domain-migration.test.mjs`、`npm run check:en`、`npm run build`。
- 公開前のブラウザ確認は実際のGA4タグをローカル配信し、すべての通信をPlaywrightで差し替えた隔離ブラウザで行う。GA4 collectは記録後204の模擬応答にし、外部へ送信しない。外部サイトやVercel Analyticsも遮断する。
- 主要4HTTPSページと規約・プライバシーのcanonical・本文・リンク・sitemapを維持する。今回のSEO変更は追加しない。Search Consoleの送信・検証・設定操作はしない。
- 公開する際は、Vercelのドメイン設定に旧ホスト→新ホストの転送が別途残っていないか確認する。存在する場合、案内を配信する同じProductionデプロイへ接続する設定が必要。上位のドメイン転送はこのコードでは解除できない。今回、その管理画面は操作していない。
- デプロイ後に旧 `/`・`/en/`・`/access`・`/en/access/` が200、Locationなし、noindexであること、旧robotsがテキスト、画像・SW・確認ファイルがHTML化されていないこと、未知URLが404であることを確認する。
- 新 `/`・`/en/`・`/access/`・`/en/access/` は200・自己canonicalのまま。HTTP→HTTPS正規化も確認する。

## 制約

- 本番Vercelエッジでの実行はデプロイ後の確認が必要。ローカル検証は公式routing-utilsの検証と、コンパイルされた設定順序の再現である。
- 以前の308がブラウザに残っていると、旧ホストへ通信せず新サイトへ移動する場合がある。その場合も新側のマーカー整理は機能するが、旧案内の表示は保証できない。
- 旧ドメインにインストール済みのPWA・既存SWのオフラインキャッシュは今回変更・削除していない。オフラインでは以前の地図が出る可能性がある。ホーム画面の登録先はユーザー自身で新URLに更新する必要がある。
- JavaScript全体を無効にした場合も案内と新トップへのリンクは表示されるが、深いパス・クエリ・ハッシュの引き継ぎと英語切替はJSが必要。GA4だけの拒否・遮断は引き継ぎを妨げない。
- 既存の `tests/search-data.test.mjs` は参照先の `scripts/search-data-runtime.mjs` と `scripts/search-data-validation.mjs` がなく、変更前から実行不能。今回の回帰と区別する。
