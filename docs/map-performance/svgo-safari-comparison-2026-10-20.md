# SVGOによる地図軽量化と実Safariでの比較（2026-10-20）

## 結果

英語版のSVG容量は大きく減るが、今回の条件で拡大縮小のFPSが明確に改善したとは判断できない。日本語版は追加の容量削減も小さい。目視で部屋・文字・記号の欠落や位置ずれは見つからなかったが、画素単位では輪郭などに微差があり、完全一致ではない。

Version 3.1以降の検討用。`refactor/map-scale` で実験し、元SVG・本体の拡大縮小処理・通常ビルドには適用していない。

## 比較条件

- 対象コミット: `cb403e0a0c882b0de79ae0182a3a98988f9097e4`。
- macOS 27.0.1、実アプリのSafari 27.0.1。PlaywrightのWebKitやiPhoneシミュレーターは使用していない。
- Safariウィンドウのコンテンツは試行終了時すべて1025×1132、アプリiframeと地図の表示領域は全試行960×800 CSS px、DPR 1。
- Viteのproduction buildを一度作り、同じJS・CSS・JSON・画像URL構成を `/baseline/` と `/svgo/` から提供。後者の地図SVGだけをSVGO 4.1.0で変換する。元ファイルは上書きしない。
- SVGO設定: `multipass: true, floatPrecision: 5, plugins: ['preset-default']`。原本16画像に加え、旧食事ピクトグラム除去後の閲覧用1F日英2画像も別途最適化した。
- `scale()` と4フレームに1回の描き直し、最大倍率、食事ピンは同一。mask/filterの専用の置き換えやタイル化は行っていない。
- 比較用localhostだけService Workerのキャッシュ処理を無効にし、資産に `Cache-Control: no-store` を付けて前後の混在を避けた。通常アプリのService Workerは変更していない。

## 拡大縮小のFPS

日英の1F・5Fについて、各条件4試行、計32試行。同じ階では元→SVGO→SVGO→元→SVGO→元→元→SVGOの順序で交互に測った。毎試行、ページと画像を読み直し、24段階の拡大・縮小でウォームアップしてから計測した。

本体のwheelイベントハンドラへ同じ合成ホイール入力を送り、24フレームの拡大・24フレームの縮小を3往復した。1段階の倍率は本体どおり1.1倍。計測中に上限で止まる時間を作らない。停止後の18フレームは別枠、拡大後のドラッグ60フレームも別枠で記録した。

FPSは同一オリジン親ページの `requestAnimationFrame` 間隔から算出した操作更新の指標で、GPUが実際に表示したフレーム数の直接計測ではない。実トラックパッドのピンチ操作の値でもない。前後比較を同じ方法に固定している。

### 各4試行の中央値

| 対象 | 元のFPS | SVGOのFPS | 差 | 元のp95フレーム時間 | SVGOのp95フレーム時間 |
|---|---:|---:|---:|---:|---:|
| 日本語1F | 32.03 | 31.64 | -1.22% | 127.5ms | 128.5ms |
| 英語1F | 31.58 | 32.04 | +1.46% | 131.5ms | 130.0ms |
| 日本語5F | 60.30 | 60.21 | -0.15% | 18.0ms | 18.0ms |
| 英語5F | 60.26 | 60.21 | -0.08% | 18.0ms | 18.0ms |

中央値の差は約1.5%以内。今回の4反復で一貫した改善は確認できない。5Fは約60FPSで頭打ちになっており、その先の余力の差は分からない。

### ばらつきと長い停止

| 対象 | 元のFPS範囲 | SVGOのFPS範囲 | 元の最大フレーム時間 | SVGOの最大フレーム時間 |
|---|---:|---:|---:|---:|
| 日本語1F | 29.61–32.38 | 31.58–32.45 | 344ms | 276ms |
| 英語1F | 31.37–31.89 | 31.66–32.21 | 279ms | 276ms |
| 日本語5F | 60.28–60.38 | 48.68–60.76 | 23ms | 394ms |
| 英語5F | 42.23–60.33 | 58.66–60.30 | 657ms | 90ms |

日本語5FのSVGO版と英語5Fの元画像で、それぞれ1試行に大きな低下が出た。原因は特定していない。元画像・SVGO版のどちらにも単発の停止があり、都合のよい試行を除外していない。停止後の区間には最大662msのフレームもあるため、中央値だけで「引っかかりがなくなった」とは判断しない。すべてのフレーム間隔と停止区間をJSONに保存した。

拡大縮小の採用サンプルは144フレーム×32試行=4,608フレーム。すべて `document.visibilityState === 'visible'`、地図の表示領域は同一。計測開始直前の共通environmentにはSafariを前面にする反映前の `hidden` が残るが、実測フレームの `hiddenFrames` は全試行0、各試行終了時もvisibleだった。

## ファイル容量

KBは1000bytes。gzipはローカルの `gzipSync` の値で、本番サーバーの実転送量は未計測。

| 表示用画像 | 元 | SVGO後 | 削減率 | gzip 元→後 |
|---|---:|---:|---:|---:|
| 日本語1F（食事ピクトグラム除去後） | 338.94KB | 336.19KB | 0.81% | 103.10→102.72KB |
| 英語1F（同上） | 1023.93KB | 477.01KB | 53.41% | 176.40→113.59KB |
| 日本語5F | 217.25KB | 215.29KB | 0.90% | 64.52→64.22KB |
| 英語5F | 673.71KB | 309.42KB | 54.07% | 116.56→76.69KB |

原本16画像の合計は7,603,190→4,835,827bytes（36.40%削減）。gzip合計は1,787,753→1,444,916bytes（19.18%削減）。閲覧用1Fの派生画像2枚はこの合計に重複加算していない。

英語1Fなどのテキスト量の減少は大きいが、今回の操作中FPSはほぼ同じだった。容量削減を、そのままSVGの描き直しコストの減少とは扱わない。

## 見た目

実Safariで18画像それぞれを白背景のcanvasに描画し、全体1倍・全体4倍・10倍で教室領域を1600×1100pxに切り出した3条件、計54条件のRGB値を比較した。10倍の切り出し中心は画像の横70%・縦45%。全画像の隅々まで10倍で比較したわけではない。

| 条件 | いずれかのRGB値が変わった画素の最大割合 | RGB差が32/255を超えた画素の最大割合 |
|---|---:|---:|
| 全体1倍 | 0.467780% | 0.030414% |
| 全体4倍 | 0.118204% | 0.000948% |
| 10倍の教室領域 | 0.144375% | 0.000966% |

1倍で差の大きかった日英2Fの領域、10倍の1F教室領域、全18画像の前後一覧を目視確認した。見た範囲で部屋・文字・記号の欠落や位置ずれは見つからない。差分は主に輪郭や細い線の描かれ方に見えるが、全画素差の原因を特定したわけではない。上の閾値は記述統計であり、見た目の一致を保証する合否基準にはしていない。

canvasでの比較はSVGの描画自体が対象。HTMLのピン・施設リング・カードまで画像比較したものではない。実Safariのアプリ表示とフロア切り替え、拡大縮小・ドラッグも実行し、描画中のエラーイベントは0だった。開発者コンソールの全ログは未取得。

## 成果物と再実行

- `output/svgo-safari-2026-10-20/performance.json`: 32試行の生フレーム間隔、表示中の画像URL、viewport、可視状態、エラー。
- `assets.json`: 元とSVGOのbyte数、gzipサイズ、使用した設定。
- `visual.json`: 全54条件の画素差。
- `summary.json` / `summary.md`: 集計。外れ値を含む試行範囲と停止時間も保持。
- `appearance-comparison.png`: 差の大きい領域と高倍率の前後比較。
- `appearance-overview-1.png`〜`3.png`: 全18画像の前後一覧。
- `visual-*-before.png` / `after.png` / `diff.png`: Safariで描いた画像・差分。差分の赤色は差を強調している。
- `optimized/`: 比較に使ったSVG。

```sh
npm install --prefix /tmp/oic-svgo-tools --no-audit --no-fund --ignore-scripts svgo@4.1.0
node node_modules/vite/bin/vite.js build --manifest --outDir /tmp/oic-svgo-build
SVGO_MODULE=/tmp/oic-svgo-tools/node_modules/svgo/lib/svgo-node.js \
  node scripts/benchmarks/svgo-safari-server.mjs \
  /tmp/oic-svgo-build output/svgo-safari-2026-10-20 5191
```

実Safariで `http://127.0.0.1:5191/` を開く。「見た目の画素比較」と「FPS比較」を順に実行し、FPS計測中はSafariを前面に維持する。iframeがウィンドウに完全に収まることを確認する。`?run=visual` / `?run=perf` で自動開始も可能。

終了後、次で集計する。Pillowがあれば比較一覧PNGも生成する。

```sh
python3 scripts/benchmarks/summarize-svgo-safari.py output/svgo-safari-2026-10-20
```

SVGOは一時ディレクトリにのみ導入しており、この検証のためにプロジェクトの依存関係やlockfileを変更していない。
